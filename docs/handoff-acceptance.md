# 调律交接接收手册（旧档演练版）

本手册规定：拿到旧调律档后，**先核验哪一份候选材料、今天能签什么、什么条件下必须延后**。
全部判断都能用仓库内样例离线复算，命令见文末。

## 1. 档案现状

旧调律档只剩两件东西：

| 档案件 | 内容 | 本仓库对应 |
|---|---|---|
| 打印表 | 各管基线基音的书面记录，无原始频峰 | 由 `examples/sample.json` 的 `pipes`/`opened` 复原 |
| 已找回的基线原始峰表 | 7 条原始频峰、开管名单、20 °C 温标 | `examples/handoff/baseline.json` |

打印表本身不能当证据：它没有原始峰表可回查，也说不清当时开的是哪几支管。基线原始峰表是唯一已核验过的底稿。

复测有两场，档案员今天只核完了一场的三件套：

- **原始峰表**：峰高、峰名与打印表能否逐条对上；
- **开管名单**：当次实际打开了哪几支管；
- **温标**：当次实测温度，以及参考温度口径（20 °C）。

另一场要等明天。**三件套没核完的复测，一律不能当作签发证据**（见 §5）。

## 2. 两份候选材料

| 材料 | 开管名单 | 录到的峰 | 能证明什么 |
|---|---|---|---|
| **合奏**（`ensemble.json`） | 低音甲、独管丙 | 各自的可信基音 220 Hz、312 Hz | 两管的基音在 20 °C 下重复出现 → 可判稳定性 |
| **独奏**（`solo.json`） | 仅低音甲 | 二倍频 440 Hz | 低音甲/2 槽独占存在 → 只能给争用峰一条旁证 |

两份材料的证据类型不同，**不能互相顶替**：

- 合奏的开管数大于 1，`isolated_support` 直接跳过整场（`pipeatlas/take_evidence.py:7`），所以它给不了任何单管旁证；
- 独奏只录到二倍频，没有基音，`stability` 里低音甲只有 1 个点（`pipeatlas/take_evidence.py:24-34`），所以它给不了任何调律判断。

## 3. 不同交接目的 → 先验哪份

| 交接目的 | 先验材料 | 先验通过后解锁的**那一项** | 为什么不能换另一份 |
|---|---|---|---|
| 对一支基线有明确基音的管签发调律判断 | **合奏** | `handoff.低音甲 = ready`、`handoff.独管丙 = adjust` | 独奏无基音，稳定性停在 `pending`，`handoff` 必为 `pending` |
| 把相邻争用槽列为有独奏旁证的复查对象 | **独奏** | `handoff.高音乙 = review` | 合奏开管数大于 1，`isolated` 全为 `unconfirmed`，`handoff.高音乙` 停在 `pending` |

矩阵（可直接复算）：

| 材料核验情况 | 低音甲 签发调律判断 | 高音乙 列复查对象 |
|---|---|---|
| 两份都未核验 | 否 | 否 |
| 仅核验合奏 | **是** | 否 |
| 仅核验独奏 | 否 | **是** |
| 两份都已核验 | 是 | 是 |

**两条硬规则**：

1. 只核验一份时，只能解锁对应的一项；不存在“任选一份即可两项通吃”。
2. 今天的时间只够核一份时，按**今天的交接目的**选：要签字就先核合奏，要派复查就先核独奏。两者都要，就必须两份都核完。

判定规则（与代码一致）：

- **签发调律判断**：基线有可信基音，且至少一场已核验复测为同一支管提供可信基音（`count ≥ 2`、`spread ≤ stability_limit`）。满足后 `handoff` 取 `ready`（基线合格）或 `adjust`（需调律）。
- **列有独奏旁证的复查对象**：某场复测开管名单**恰好只有这一支管**，其独占归属的槽位与该争用峰的候选槽重合（`pipeatlas/take_evidence.py:4-21`）。满足后 `handoff` 取 `review`，表示“有旁证的复查对象”，**不是**调律结论。

口径提醒：`isolated` 按**频峰**出行（峰乙、峰戊），`handoff` 按**音管**出行（高音乙）。两者是同一件事的两端——
单管复测证明的是相邻槽位 `低音甲/2` 确实存在，于是把落在 `高音乙/1` 的争用峰所在音管列为复查对象。
它**不**证明峰乙应归高音乙，手册与签发措辞都不得越过这一步。

## 4. 今天能签的措辞

以下措辞均以“合奏材料已核验、温标 20 °C”或“独奏材料已核验、温标 20 °C”为前提。
数字取自 `python3 -m pipeatlas.check_handoff` 的复算输出。

### 4.1 基线合格、复测同值 —— 低音甲

> 低音甲基线可信基音为峰甲 220.0 Hz（20 °C，偏差 0.00 音分）。
> 已核验合奏复测：开管名单低音甲、独管丙，温标 20 °C，原始峰表逐条对上。
> 该复测中低音甲基音偏差 0.00 音分，与基线极差 0.00 音分（限值 5 音分）。
> **签发：调律合格，无需调整。**

### 4.2 基线待调、复测同值 —— 独管丙

> 独管丙基线可信基音为峰丙 312.0 Hz（20 °C，偏差 +11.13 音分，超出 5 音分通带）。
> 已核验合奏复测：该管基音偏差 +11.13 音分，与基线极差 0.00 音分。
> **签发：待调律，建议下调约 11.1 音分。**

### 4.3 争用槽 → 有独奏旁证的复查对象 —— 高音乙

> 高音乙基线基音未独占归属：峰乙、峰戊同时落在高音乙/1 与低音甲/2，属争用。
> 已核验独奏复测：仅开低音甲，录到二倍频 440.0 Hz，独占归属低音甲/2。
> 据此把相邻争用槽**高音乙/1**列为有独奏旁证的复查对象。
> **签发：派复查；不作高音乙的音准结论。**

### 4.4 不能这样写

| 错误措辞 | 问题 |
|---|---|
| “低音甲稳定，可调” 但只核了独奏 | 独奏无基音，稳定性仍是 `pending`；`handoff` 必为 `pending`，不能签 |
| “高音乙有独奏佐证，已确认归属” | 单管复测证明的是低音甲/2 槽存在，**不能反证峰乙归高音乙**；只能列复查 |
| “合奏复测已支持单管佐证” | 开管数大于 1 的复测整场不进 `isolated`，此说法无来源 |
| “所有原复测都支持稳定” | 见 §5，全称声明需要**每场**复测都核验，今天只有一场 |

## 5. 必须延后签发的条件

| 条件 | 现象（可复算） | 处置 |
|---|---|---|
| 合奏材料未核验 | `stability.低音甲 = pending`（`count=1`），`handoff.低音甲 = pending` | 不签任何调律判断，等三件套核完 |
| 独奏材料未核验 | `isolated.峰乙 = unconfirmed`，`handoff.高音乙 = pending` | 不列复查对象 |
| 复测开管名单不是恰好一支管 | `two-open-no-solo.json`：开低音甲+高音乙、只录 440 Hz，`isolated` 仍全 `unconfirmed`，`handoff.高音乙 = pending` | 该场不能作单管旁证；重开单管再测 |
| 温标未核验或与基线口径不符 | `ensemble-24c.json`：同一场合奏复测记成 24 °C，`handoff.低音甲/独管丙` 全部变 `revisit` | 温标是结论的开关，未核温标不得签发 |
| 已核验复测与基线不一致 | `stability.* = drift`（`spread > 5`） | `handoff` 转 `revisit`，撤回签发，先复测 |
| 声明范围是“所有原复测” | 见下节 | 逐场核验完之前不签全称声明 |
| 基线本身无可信基音（如背管丁） | `tune = pending`、`deviation = null` | 只按 `revisit` 排序派测，不签音准 |

**延后不等于拒收**：`revisit` 是“需要再测”，不是“这支管坏了”。档案员明天核完第二场后，按 §3 重跑矩阵再签。

## 6. 为什么不能把“工作台当前显示的稳定”沿用到“所有原复测都支持稳定”

### 6.1 显示范围 ≠ 档案范围

`stability` 的点集只有两类来源（`pipeatlas/take_evidence.py:24-32`）：

1. 基线 `tune` 里 `deviation` 非空的管；
2. **已载入**的复测批次里 `deviation` 非空的管。

也就是说，工作台显示的是“**当前载入的这几场**”的稳定性，不是“旧档里所有复测”的稳定性。今天只核完一场、只载入一场，显示 `stable` 只是这一场的结论。把它升级成全称命题，等于偷偷把“已载入”换成了“所有”，而这两者今天恰好不等。

还有一层容易看错：`tune` 表的 `ready` 和 `handoff` 表的 `ready` 不是一回事。只看基线时，低音甲的 `tune.state` 已经是 `ready`（偏差 0.00 音分在通带内），但它的 `handoff.state` 仍是 `pending`，因为还没有一场已核验复测。拿 `tune` 的“已符合”直接当交接结论，就是把手上的基线显示冒充成了复测稳定性。

### 6.2 反例：一场尚未核验的复测确实会推翻它

`examples/handoff/counterexample.json` 在合奏复测之外，加入打印表上另一场待核复测：

- 开管独管丙，温标 24 °C，原始峰表记 312.0 Hz；
- 它的三件套**今天还没核**，所以不能当签发证据；
- 但一旦按记录成立，它就**足以推翻**“所有原复测都支持稳定”。

复算结果：

| 量 | 值 |
|---|---|
| 基线独管丙偏差（312.0 Hz @20 °C，目标 310.0 Hz） | +11.133376 音分 |
| 待核复测偏差（312.0 Hz @24 °C，目标 312.107792 Hz） | −0.598018 音分 |
| 散布（按各自温度修正） | **11.731395 音分 > 5** |
| `stability.独管丙.state` | **drift** |
| `handoff.独管丙.state` | **revisit** |

而低音甲不受影响，仍是 `handoff = ready`。这正好说明：**一场复测能推翻的只是它涉及的那支管**，不能因为低音甲还稳着，就替独管丙背书。

### 6.3 温度陷阱：不修正会得到“假稳定”

这场待核复测的原始频率与基线峰丙**同为 312.0 Hz**。若直接比赫兹：

```
312.0 vs 312.0  →  散布 0.000000 音分  →  假 stable
```

按每场自己的温标换算后再比音分（`pipeatlas/sessions.py:20-22` 除以原始参考温标，而非冻结首场温度）：

```
基线  : 312.0 / 310.000000  = +11.133376 音分
复测  : 312.0 / 312.107792  =  -0.598018 音分
散布  : 11.731395 音分  →  drift
```

所以“所有原复测都支持稳定”这句话，今天既没有证据基础（只有一场核完），也有一个明确的潜在反例（待核那场）。

### 6.4 今天该怎么说

可以签：

> 在**已核验的一场**合奏复测（20 °C）中，低音甲与独管丙的基音偏差与基线一致（各 0.00 音分，限值 5 音分）。

不能签：

> 所有原复测都支持稳定。

后者要等旧档里**每一场**复测的原始峰表、开管名单、温标都核完，并且逐场按各自温度换算后都落在限值内。待核那场明天若核出漂移，独管丙的签发要撤回并转 `revisit`；若核不上打印表，则整场作废，也不能拿它当“稳定”的补证。

## 8. 复算

```sh
python3 -m pipeatlas.check_handoff
```

脚本离线读取上表样例，走与生产相同的归约链路（`domain.parse → harmonics.evaluate → rules.decide → review.analyze_review`），
复核每份成果的摘要，并断言：

1. 单份材料只解锁一项，两份齐备才两项都可交接；
2. 基线 `tune.state=ready` 但 `handoff.state=pending`：显示范围不能升级成交接结论；
3. 合奏给出 `stable` 与 `ready/adjust`，且 `isolated` 全 `unconfirmed`；
4. 独奏给出 `supported`，但低音甲稳定性停在 `pending`；
5. 双开复测不构成单管佐证；
6. 待核复测把独管丙推到 `drift`，散布 11.731395 音分；
7. 直接比赫兹会得到 0.000000 音分的假稳定；
8. 合奏温标改为 24 °C 时结论翻转，证明温标必须列入核验。

期望输出（节选）：

```
材料核验情况        低音甲 签发调律判断          高音乙 列复查对象
两份都未核验        否                   否
仅核验合奏         是                   否
仅核验独奏         否                   是
两份都已核验        是                   是

反例独管丙 stability = {"count": 3, ..., "spread": 11.731394528501554, "state": "drift"}
温度陷阱：直接比赫兹散布 0.000000，按各自温度修正后 11.731395
```

脚本还打印每份样例的成果摘要；同一输入应复现同一摘要，可用来核对旧档回放是否被改动。

## 9. 交接清单（打印出来贴在档案柜）

- [ ] 今天的交接目的是“签调律判断”还是“派复查对象”？只够核一份时按目的选材料。
- [ ] 要签的那场复测，原始峰表、开管名单、温标三件套都核了吗？
- [ ] 开管名单是“恰好一支管”吗？不是就不能当单管佐证。
- [ ] 每场复测是否按**自己的**温度换算后比音分？
- [ ] 结论落到哪支管？一场复测只对涉及的管负责。
- [ ] 是否在写“所有”“全部”？没核完就降级成“已核验的 N 场”。
- [ ] 出现 `drift` / `revisit` 时，撤回对应签发，不撤回其他管的。
