# 档案交接手册：维修换管场景下的音管身份与封存证据沿用规则

- 演练对象：东厢管风琴（合成演练数据，不接真实设备）
- 配套工单：WO-2026-1120-换管（2026-11-20 维修，换管槽换装另一根物理音管）
- 适用系统：音管泛音归属台（pipeatlas），数据合同版本 1
- 交付日期：2026-11-23
- 配套材料：`原始包/`（四个输入包＋身份交叉表）、`器材交接表.json`、`复算/`（独立复算脚本与全部复算产物）
- 边界声明：本手册及配套材料不修改任何系统代码，也不改动原始包；所有封存均写入临时库，演练结束即清除

## 1. 为什么需要这本手册

系统按**槽位标识**（输入里的 `pipes[].id`，如「换管槽」）归约频峰、出调律报表，并按 SHA-256 摘要封存。它不登记槽位里装的是哪一根物理音管。维修时同一槽牌可以换装另一根管，于是出现一个必须由人工流程兜底的事实：

> **摘要校验回答的是「这个包自封存后有没有被改过」，不是「槽位里的物理音管有没有被换过」。**

本手册演练在《器材交接表》登记了物理身份生效区间时，如何把外部身份见证与系统槽位交叉，区分三类证据，并给出每类证据允许发布到的级别。

### 1.1 三个槽位、两根换过的管、一个无见证的档

| 槽位（系统标识） | 维修前物理音管 | 维修后物理音管 | 身份见证 |
|---|---|---|---|
| 换管槽 | P-017-旧管（生效止 2026-11-20） | P-204-新管（生效起 2026-11-20） | 换装工单＋新旧管扫码，区间不相交 |
| 沿用槽 | P-018-沿用管 | P-018-沿用管（同一根） | 未拆动签注＋封条编号连续，区间贯穿维修日 |
| 无凭槽 | P-019-身份存疑管 | 无法确认是否原管 | 无任何拆装/扫码/封条见证 |

### 1.2 四个封存包

| 包 | 时点 | 是否含复核录音 | 完整摘要（前16位） |
|---|---|---|---|
| 甲-维修前基础包 | 维修前 | 否 | `ad43d0e9e4166e08` |
| 乙-维修前复核包 | 维修前 | 是（旧管/沿用管单录） | `378b46df26a8001d` |
| 丙-换管后基础包 | 维修后 | 否 | `8e6efb4eaf841f2c` |

## 2. 术语与判定口径

| 术语 | 含义 |
|---|---|
| 槽位 | 系统中的逻辑位置标识，维修前后保持不变 |
| 物理音管 | 可拆装的实体，以器材编号（P-xxx）标识；同一槽位可先后容纳多根 |
| 生效区间 | 器材交接表登记的某物理音管占据某槽位的起止日期；取证日期落入哪个区间，证据就归属哪根管 |
| 身份见证 | 工单签注、出入库扫码、封条连续性等能证明「是不是同一根管」的外部记录 |
| 单场读数 | 一次合奏开管中得到的归属与调律行，只对当次取证负责 |
| 可信交接 | 系统 `handoff` 输出中的 `ready`/`adjust` 等确定态，要求当次调律结论与 `stability=stable` 同时成立 |
| 稳定性重建 | 换管后用新物理管自己的两次以上录音，按各自温度修正后重新算出音分极差 |

系统内部的硬口径（交接时不得绕过）：

1. **频峰与泛音槽必须相互唯一才归属**，不按最小误差强行匹配（`allocation.py`）。
2. **可信基音缺失时不给调律偏差**，`tune` 行为 `pending`。
3. **稳定性需要可信基音的两个以上比较点**，且每个复测批次按自己的温度重算温度比（`take_evidence.py`、`sessions.py`）；只有一个点时状态为 `pending`。
4. **`handoff` 的确定态要求 `tune` 与 `stability` 双成立**；只要稳定性是 `pending`/`drift`，交接行就退回 `pending`/`revisit`（`triage.py: tune_handoff`）。
5. **跨对象比对被系统拒绝**（409），同对象同合同版本才可 `compare`；同一输入重复封存只写一次。

## 3. 物理身份生效区间的使用规则

### 3.1 取证日期归属

对任何一条证据（基线读数、复测录音、封存包），先取它的取证日期，再到器材交接表查槽位的生效区间：

- 日期落入区间 A → 证据属于区间 A 的物理音管；
- 区间在维修日断开（换管槽）→ 断点两侧的证据分属两根管，**禁止跨断点合并稳定性、禁止沿用断点前的调律承诺**；
- 区间连续且有未拆动见证（沿用槽）→ 两侧证据属于同一根管，允许跨档合并解释；
- 查不到有效区间或见证缺失（无凭槽）→ 身份按「存疑」处理，**默认按换过管对待**，直到补证。

### 3.2 摘要能证明什么、不能证明什么

- 能证明：封存包的 `source` 与 `outputs` 自写入起未被篡改（`verify_packet` 双重摘要核对，篡改即 409）。
- 不能证明：槽位内物理音管的连续性。本演练中甲乙两包与丙丁两包都各自通过摘要校验，但换管槽里已经是另一根管。
- 因此交接裁决的证据链是两段式：**摘要保完整性（系统负责）＋ 交接表保身份（人工流程负责）**，缺一不可。

## 4. 三类证据的区分规则（核心）

### 4.1 可跨档沿用的另一支管 —— 以「沿用槽」为例

**判定条件（同时满足）**

1. 器材交接表中该槽位只有一条贯穿维修日的生效区间；
2. 有未拆动签注或封条连续等身份见证；
3. 新旧包内该管的结论均由系统正常归约产生。

**本演练数据**

- 乙包（维修前）：沿用槽 `tune=ready`、偏差 0.0 音分；`stability=stable`（基线与「旧-沿用槽单录」极差 0.0）；`handoff=ready`。
- 丁包（维修后）：偏差移至 4.035 音分（仍在 ±5 音分调律带内）；21 ℃ 单录按当次温度修正后为 −0.065 音分，与基线极差 4.10 ≤ 5，`stability=stable`，`handoff=ready`。

**允许的沿用**

- 乙包已经成立的稳定性与交接承诺可跨档沿用，丁包结果对其再确认；
- 乙包旧录音与丁包新录音可合并叙述同一物理管 P-018 的长期表现；
- 偏差漂移（0.0 → 4.035 音分）登记备查，不需因此吊销承诺，但应列入下次复测关注项。

### 4.2 只能证明单场读数的旧证据 —— 以「换管槽」的甲、乙包为例

**判定条件**

- 槽位生效区间在维修日断开，旧区间已随拆除登记终止；旧包的取证日期全部落在旧区间。

**本演练数据**

- 甲包换管槽：`tune=ready/0.0`，证据峰「主峰换」；
- 乙包换管槽：`stability=stable`（旧管单录，极差 0.0）、`handoff=ready`。

**这些证据现在还能说明什么**

- 只能证明 **P-017-旧管** 在旧取证日期的那场读数与那段时间的稳定性；
- 可作为旧管的历史档案、维修对照和故障追溯依据保留；
- **不得**用于支撑 P-204-新管的任何调律承诺、稳定性结论或交接放行。

### 4.3 必须以换管后录音重建的稳定性 —— 以「换管槽」的丁包为例

新管 P-204 在丁包之前没有任何属于自己的录音；基音读数即使与旧管完全相同，也不携带任何跨时间稳定性信息。重建方式：

1. 换管后安排至少两次单管开管录音（本演练为「新-换管槽甲录」21 ℃、「新-换管槽乙录」20 ℃）；
2. 每次录音按**各自温度**重算温度比后再求音分（系统在 `sessions.py` 内建此口径）；
3. 与换管后基线合并取极差：本演练三点为 0.0 / 2.238 / 2.595 音分，**极差 2.595 ≤ 限值 5 → `stability=stable`**；
4. 与当次 `tune=ready` 双成立，丁包 `handoff=ready` 才对新管生效。

注意：重建出的承诺只引用换管后区间的证据；乙包旧管录音不得计入新管的比较点。

## 5. 陷阱演练：频率与报表行完全一样，仍不能沿用旧调律承诺

这是本次交接最关键的反例，验收时应能现场复算。

### 5.1 现象

甲包（旧管）与丙包（新管）中，换管槽在全部八个归约阶段的报表行**逐行完全相等**：

| 阶段 | 换管槽相关行数 | 甲 vs 丙 是否相等 |
|---|---|---|
| target 音温换算 | 1 | 相等 |
| candidate 泛音候选 | 2 | 相等 |
| assign 独占归属 | 2 | 相等 |
| conflict 冲突证明 | 0 | 相等 |
| coverage 音管缺测 | 1 | 相等 |
| tune 调律核对 | 1 | 相等（均为 ready/0.0 音分，证据峰同为「主峰换」） |
| revisit 复测次序 | 0 | 相等 |
| clusters 频峰争用组 | 0 | 相等 |

- 两包都能通过各自的摘要完整性校验；
- 整包 `compare` 仍能检出另外两个槽位共 10 行差异（沿用槽、无凭槽的频率在维修后微调），但**没有任何一行差异属于换管槽**；
- 即：系统层面看，换管槽「什么都没变」。

### 5.2 为什么仍然不能沿用

1. 器材交接表显示该槽位生效区间在 2026-11-20 断开：P-017 拆除、P-204 换装，物理身份已变；
2. 报表行相同只说明两根管在各自那场合奏中的基音都落在 200 Hz、偏差都是 0.0 音分——这是**两个不同实体各自的单场读数恰好相同**；
3. 旧管的稳定性（乙包）是旧管自己两次测量的关系量，与新管无关；新管在丁包录音之前不存在任何跨时间证据；
4. 若仅凭同频同表沿用旧承诺，等于让新管「借用」了它从未参与过的证据，违背可信基音与稳定性的取证归属原则。

### 5.3 正确处置

- 甲、乙包对换管槽降格为 P-017 的历史档案（单场读数级保留）；
- 新管稳定性只由丁包两条换管后录音重建（极差 2.595 音分，stable）；
- 新管的 `handoff=ready` 生效日期不得早于 2026-11-20，证据清单只能列「新-换管槽甲录/乙录」。

## 6. 无身份见证但前后偏差接近的档：能发布到哪一级

### 6.1 现象（无凭槽）

- 维修前后均无拆装签注、扫码或封条记录，器材交接表标为「身份存疑」；
- 甲包偏差 0.0 音分，丙包偏差 2.307 音分——两次读数都在 ±5 调律带内，偏差接近；
- 乙、丁两包都没有该槽位的单管录音，稳定性比较点始终只有基线 1 个：`stability=pending`，`handoff=pending`；
- 丁包 `silence` 开管缺测账对该槽位记为 `blind`（复核中从未被有效观测）。

### 6.2 为什么「偏差接近」不能替代身份见证

- 调律偏差是单场测量量，两根不同的管也可以碰巧都落在调律带内；数值接近不构成同一性证明；
- 系统口径本身也没有授予交接资格：比较点不足两个时稳定性只能是 `pending`，`handoff` 随之 `pending`；
- 在身份存疑未补证前，按「换过管」处理是唯一保守且可审计的选择。

### 6.3 发布分级

本手册把可对外的发布强度分为三级：

| 级别 | 含义 | 所需证据 |
|---|---|---|
| L1 单场读数/内部参考 | 某次取证的归属与调律行，可作内部观测与历史档案 | 封存包摘要有效、当次归约合法 |
| L2 带稳定性的调律结论 | 同一物理管在自己生效区间内有 ≥2 个温度修正后比较点，`stability=stable` | L1 ＋ 区间内复测录音 |
| L3 可信交接承诺 | 系统 `handoff` 确定态（ready/adjust），可对下一班组放行 | L2 ＋ 身份见证覆盖证据全部时间跨度 |

**无凭槽的最高发布级 = L1**：四个包各自的单场读数可以发布为内部参考；禁止发布 L2/L3，禁止把维修前后读数串成稳定性叙事。补证路径：补登器材交接表身份区间，并补做两次以上换管后单管录音，使稳定性取得 ≥2 个比较点后再重新评定。

### 6.4 三个槽位的发布级对照

| 槽位 | 维修前包可发布级 | 维修后包可发布级 | 跨档沿用 |
|---|---|---|---|
| 换管槽 | 甲 L1；乙对旧管 P-017 可达 L3（仅限旧区间） | 丙 L1；丁对新管 P-204 达 L3（仅引用换管后录音） | 禁止；稳定性已重建 |
| 沿用槽 | 甲 L1；乙 L3 | 丙 L1；丁 L3 | 允许，承诺跨档沿用并登记漂移 |
| 无凭槽 | 甲 L1；乙 L1（handoff=pending） | 丙 L1；丁 L1（handoff=pending） | 禁止；补证前按换管处理 |

## 7. 标准交接操作流程

1. **收包**：取得维修前后各档输入包与封存包，核对对象 `id` 一致、合同版本均为 1。
2. **验封**：对每个封存包执行摘要核对（系统 `verify_packet` 或本演练 `复算脚本.py` 的独立重算）；任何一包失败即中止交接。
3. **对身份**：打开器材交接表，逐槽位抄录物理音管编号与生效区间，标注维修日断点。
4. **做交叉**：在身份交叉表中把每个槽位的区间、见证、各包行据（tune/stability/handoff）填入；无见证槽位直接标「存疑」。
5. **判三类**：按第 4 章规则把每个槽位归入「可跨档沿用／仅单场旧证据／需重建稳定性」。
6. **查陷阱**：对报表行完全未变的槽位（本演练换管槽），必须回到交接表核对区间，禁止以系统无差异为由沿用承诺。
7. **定级别**：按第 6.3 节三级表确定每个槽位的发布级，在交接文件上写明证据清单与生效日期。
8. **留痕**：封存台账、交叉表、复算报告随交接包归档；所有人工结论都要能回溯到具体摘要与区间记录。

### 交接检查清单

- [ ] 四个封存包摘要全部独立复算通过
- [ ] 器材交接表每个槽位的生效区间与工单、扫码/封条见证一致
- [ ] 换管槽旧承诺已标记「不沿用」，新稳定性的比较点全部晚于 2026-11-20
- [ ] 沿用槽跨档沿用有连续区间与未拆动见证支撑，漂移量已登记
- [ ] 无凭槽发布级不超过 L1，补证路径已写入交接备注
- [ ] 篡改/非法输入演练已完成且仅作用于内存副本，原始包与封存库未改动

## 8. 复算与材料索引

### 8.1 如何独立复算（不依赖系统归约代码的部分）

```sh
python3 -I handoff-drill-20261123/复算/复算脚本.py \
  handoff-drill-20261123/原始包 \
  handoff-drill-20261123/复算 \
  /workspace
```

脚本用标准库独立重算温度比、目标频率、音分偏差（`1200·log₂(实测/目标)`）、候选边、独占归属与复测极差，并独立重算两级 SHA-256 摘要，再与真实工作台的输出逐项对账；随后在临时 SQLite 库中演练封存去重、`compare`、导出一致性、篡改拒绝与非法输入不落库。本次演练结果：**62 项核对全部通过**。

### 8.3 关键数值备查
